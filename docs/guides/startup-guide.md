# はじめ方とOBS設定

RHODES OBS COMMANDER3373は、アークナイツ「統合戦略」のラン情報を入力し、OBSへ表示するツールです。まず手動入力で表示を作り、必要に応じて画面認識や大会入力を追加できます。

[プロジェクトの紹介](../../README.md) · [資料一覧](../README.md)

## 1. アプリを起動する

配布ZIPを入手済みの場合の手順です。GitHubでの配布状況は[Releases](https://github.com/ratedat/RHODES-OBS-COMMANDER3373/releases)を確認してください。

1. 書き込み可能な新しいフォルダーへZIPをすべて展開します。
2. 展開先の `RhodesSuki.exe` を起動します。ZIP内から直接起動したり、EXEだけを別の場所へ移したりしないでください。
3. 上部の一覧から、使用する統合戦略テーマを選びます。

Windows x64向けの配布版には.NET実行環境を含みます。通常の手動入力を始めるために、ADBやOCRモデルを追加導入する必要はありません。

## 2. 表示する情報を入力する

| 画面 | 入力する内容 | 反映方法 |
| --- | --- | --- |
| ラン | 源石錐・等級・分隊、ボス、大会メモ | 手動補正は「反映」、大会メモは「大会情報を反映」。ボスの選択は即時反映 |
| 特殊値 | 幻覚、拒絶反応、啓示板、思案、銭など | テーマ・項目ごとの「反映」ボタンで確定 |
| 選択 | 招集したオペレーター、所持秘宝、昇進や使用状態 | 一覧から選択・編集すると保存 |

「未反映の変更あり」と表示されている入力は、まだ表示用の状態へ反映されていません。「入力を戻す」で未反映の編集を取り消せます。

新しいランを始めるときは「ランをクリア」を使い、前のランの表示が残っていないか確認してください。

## 3. OBSへ表示する

1. 左側の「出力」を開きます。
2. 「配信サーバーとURL」で「起動」を押し、稼働状態を確認します。Node.jsが見つからない場合は、同じ画面の「Node.js導入」を使用します。
3. **カスタムOverlay**の「URLコピー」を押します。
4. OBS Studioで「ソース」→「＋」→「ブラウザ」を選び、URLを貼り付けます。
5. 幅を**1920**、高さを**1080**にします。アプリ側で情報を変え、OBSの表示にも反映されることを確認します。

Node.jsの導入にはインターネット接続が必要です。アプリが実行フォルダー内へ配置するため、インストーラーの実行は不要です。

部品の位置・大きさは「出力」のレイアウト編集で調整できます。色・文字・背景の変更は[出力のカスタマイズ](output-css-customization.md)を参照してください。

### URLを使い分ける

**画面に表示されたURLをコピーする方法を推奨します。** 以下は既定ポート `5173` の例です。

| 用途 | URL |
| --- | --- |
| カスタム配置をまとめて表示 | `http://127.0.0.1:5173/overlay?layout=custom` |
| 標準の固定レイアウトを表示 | `http://127.0.0.1:5173/overlay` |
| ブラウザーで状態を確認・修正 | `http://127.0.0.1:5173/sidecar` |

Sidecarは操作用のページです。OBSへ表示する場合はOverlayのURLを使ってください。

## 4. 画面認識を使う場合

手動入力だけで使用する場合、この設定は不要です。

1. 使用するエミュレーターのADB接続を有効にし、ゲームを1280×720・16:9で表示します。
2. アプリの「接続設定」を開き、「自動検出」を押します。複数の候補がある場合は、使用中の端末を選びます。
3. 「接続・撮影」を押し、意図したゲーム画面を取得できることを確認します。
4. ゲームを探索中のマップへ戻し、上部の「画面を取得して反映」または各画面の取得ボタンを使います。
5. 取得後の内容を確認し、誤りは「ラン」「特殊値」「選択」で修正します。

取得処理は、必要に応じてゲーム内の一覧を開いたりスクロールしたりします。処理中はゲームの操作を待ってください。各取得ボタンの案内に従い、対象画面を表示して実行してください。

**歳の銭OCR（有効銭・保有銭）は停止中です。** 銭は「特殊値」から手動入力してください。

対応プリセット、ADBの場所、接続できない場合の確認項目は[ADB設定ガイド](adb-setup.md)を参照してください。

## 5. 大会で入力を分担する場合

「出力」→「大会入力（簡易公開）」から、入力担当者用のURLとコードを発行できます。担当者はブラウザーで情報を入力し、「変更を送信」で配信PCへ反映します。ADBは不要です。

簡易公開にはインターネット接続が必要です。URLとコードは入力を担当する人に共有してください。終了時は「停止」を押します。

再接続や担当交代、常設中継サーバーについては[大会遠隔入力](tournament-remote-input.md)を参照してください。

## 更新と設定の引き継ぎ

1. アプリを終了し、現在のフォルダーを保管します。
2. 新しいZIPを**別のフォルダーへすべて展開**します。EXEだけを差し替えないでください。
3. 設定を引き継ぐ場合は、旧フォルダーの `user-data` を新フォルダーへコピーします。
4. 新しい `RhodesSuki.exe` を起動し、テーマ・入力内容・OBS表示を確認します。

通常起動は新しいランから始まります。大会入力を開始した後の保存済みランは再起動時に引き継ぎますが、接続は自動再開しません。更新をまたいで大会のランを継続する場合は、旧フォルダーの `data/current-state.json` もバックアップし、両方のアプリを終了した状態で同じ場所へコピーしてください。状態を確認してからセッションを開始し直し、新しい入力URLを担当者へ渡してください。

外部中継サーバーを利用する場合は、更新内容に応じてサーバー側も更新してください。

### 配布フォルダー内の保存先

| 場所 | 内容 |
| --- | --- |
| `user-data/suki-settings.json` | アプリの設定 |
| `data/current-state.json` | 現在のラン状態 |
| `RHODES OBS COMMANDER3373 Debug Logs/` | ログ、認識画像、報告ZIP |

これらは実行中に作成・更新されます。設定やランを保管したい場合は、アプリ終了後にバックアップしてください。

## 困ったとき

| 症状 | 最初に確認すること |
| --- | --- |
| OBSに何も表示されない | 配信サーバーが稼働中か、OBSに貼ったURLがアプリの表示と一致しているか |
| 入力が表示に反映されない | 「未反映の変更あり」が残っていないか、正しいテーマを選んでいるか |
| 配信サーバーが起動しない | 「出力」に表示されたエラーとNode.jsの状態。ポートの競合なら、既存のサーバーを確認 |
| ADBが見つからない・接続できない | 「接続設定」のADBパス・端末候補と、エミュレーター側のADB設定 |
| 二重に起動できない | 同じラン状態を使うウィンドウが既に開いていないか |
| 保存状態を読み込めない | 状態ファイルをバックアップし、エラー内容を記録。再読み込みだけでは破損は修復されません |

解決しない場合は[不具合報告と機能要望](feedback.md)へ進んでください。

## ソースから起動・開発する

GitHubのソースコードから動かす場合は、[開発環境の準備](../development-setup.md)を完了してから、リポジトリのフォルダーで次を実行します。

```powershell
npm run suki:run
```

Windowsでは `start-windows.vbs` をダブルクリックして起動することもできます。この起動方法は現在のソースをビルドするため、開発環境が必要です。

テスト・ビルド・配布物の作成手順は[開発検証手順](../development-verification.md)を参照してください。
